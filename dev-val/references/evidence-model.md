## 证据分层

保持三层并建立引用：

1. **原始证据**：测试报告、退出码、日志、指标、查询结果、追踪、截图或外部系统执行记录。
2. **规范化证据**：从原始证据提取的用例结果、时间、版本、环境和失败摘要。
3. **派生结论**：`VAL/DVAL`聚合和 `GATE` 建议。

不得只保存派生结论，也不得为了方便删除首次失败或原始定位器。

## EVD结构

每个 `EVD` 至少记录：

| 字段 | 要求 |
| --- | --- |
| `id/change/version/status` | 遵循统一产物信封 |
| `run_ref` | 来源 `RUN` 及版本 |
| `test_refs` | 被证明的 `TC/AUT/TEST-*` |
| `expected_sources` | 预期或判定依据及版本 |
| `target` | 被测代码、构建、契约和配置版本 |
| `environment` | 环境身份和关键差异 |
| `observations` | 实际观察及结果，不与解释混写 |
| `raw_locators` | 原始报告、日志、指标或查询定位器 |
| `integrity` | 哈希、签名、大小或完整性说明 |
| `applies_to` | 证据可支持的明确范围 |
| `validity` | 新鲜度、前提和失效条件 |
| `redaction` | 已脱敏内容和无法保留内容 |

一个 `EVD` 应有一个主要证明目标。大型执行批次可以产生多个证据，不要用一个摘要覆盖相互独立的结论。

## 证据强度

- **强证据**：版本、环境、预期、执行、原始结果和完整性均可复核，适用范围明确。
- **有限证据**：关键上下文存在但环境等价性、选择范围或保留信息有限，只支持局部结论。
- **弱证据**：版本、环境、时间、预期或原始定位器缺失，不支持关键门禁通过。
- **冲突证据**：不同有效来源对同一目标给出不一致结果，必须保留并调查。

证据强度不能仅由工具、覆盖率、测试层级或执行次数决定。

## 有效性与失效

状态使用 `Valid → Expired / Revoked`。以下变化至少触发重新评估：

- 被测代码、依赖、契约、配置、迁移或数据语义变化。
- `TC/AUT`步骤、断言、夹具、替身或预期来源变化。
- 环境拓扑、外部依赖、时间条件或安全策略发生相关变化。
- 超过明确新鲜度期限。
- 发现报告截断、污染、伪造、错误归属或不可复现。
- 有权限责任方撤销证据。

先标记潜在影响，再根据语义差异决定 `Expired`；格式、路径或无语义重构不机械失效全部证据。

## 完整性与敏感信息

对可保存文件记录稳定定位器和哈希。原始证据过大时保留安全位置、范围、生成方式、保留期限和摘要，不把大段日志复制进产物。

脱敏凭据、令牌、Cookie、个人信息、支付数据和商业秘密。脱敏不得改变通过或失败判断；若必要信息无法保留，说明对可审计性的限制。

## 证据复用

只有被测版本、契约、配置、环境、数据条件、预期和适用范围都匹配时才能复用。跨环境推广必须证明相关差异不影响结论；“环境相似”“代码未改”或“CI之前通过”不足以自动复用。

门禁只引用当前有效且满足最低强度的证据。旧证据保留历史状态和后继关系，不覆盖或删除。
