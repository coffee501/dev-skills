## 门禁边界

`VAL/DVAL`定义需要验证的业务、架构或详细设计目标；`dev-val`不改变目标，只判断当前有效证据是否满足其聚合规则。`GATE`是验证门建议，不是发布批准、风险接受或生产稳定声明。

验证门、发布门和确认权限保持分离。没有项目授权时只输出 `Suggested`；存在明确授权记录时才能写 `Confirmed`，并保留确认人、时间、范围和依据。

## 评估输入

每个目标至少需要：

- `VAL/DVAL`编号、版本、范围和通过规则。
- 必选、可选和条件测试及其适用版本与环境。
- 当前有效 `EVD` 和来源 `RUN`。
- 失败、阻塞、跳过、隔离、未运行和过期证据。
- 证据新鲜度、最低强度和环境等价要求。
- 已授权的风险接受、例外、期限和失效条件。

聚合规则缺失时，允许列出证据覆盖视图，但相关门禁保持 `NotAssessed` 或 `Blocked`，不得自创通过阈值。

## 聚合流程

1. 锁定门禁范围、目标版本、环境和规则版本。
2. 展开适用 `VAL/DVAL` 及必选、条件和不适用测试。
3. 验证每个 `EVD` 的状态、强度、范围、新鲜度和原始定位器。
4. 排除 `Expired/Revoked`、版本不匹配和范围外证据。
5. 汇总失败、阻塞、未运行、跳过、Flaky和Quarantine影响。
6. 应用明确的聚合规则；保持逐目标结果和总体结果可追踪。
7. 检查风险接受是否有权限、范围、到期时间和失效条件。
8. 形成 `GATE` 评估结果、确认级别、理由、缺口和重新进入条件。

不要使用简单通过率、覆盖率、测试数量或“无新缺陷”替代上述流程。

## 评估结果

| 结果 | 使用条件 |
| --- | --- |
| `NotAssessed` | 尚未评估或聚合规则不存在 |
| `Pass` | 所有适用条件均由当前有效证据满足，例外已按规则接受 |
| `Fail` | 有效证据证明一个或多个强制目标不满足 |
| `Blocked` | 必要执行、证据、环境、授权或规则缺失，无法判断 |
| `Expired` | 曾有结论，但支撑证据或适用范围已经失效 |

总体结论不得掩盖逐目标状态。一个门禁可以因局部目标 `Fail/Blocked` 而整体不通过，同时保留其他目标已满足的证据。

## 风险接受与例外

Skill不能自行接受风险。输入中的风险接受至少记录责任人或角色、权限依据、范围、理由、跟踪项、到期时间和失效条件。缺少任一关键内容时作为待确认输入，不用于解除关键阻塞。

Quarantine、跳过或有限证据只有在聚合规则明确允许时才能作为例外。关键安全、权限、资金、数据一致性、不可逆迁移和恢复目标不得以普通测试数量补偿。

## 重新评估

代码、契约、配置、迁移、测试预期、自动化、环境、证据新鲜度或门禁规则变化时，创建新的 `GATE` 版本或后继编号。保留旧结论、证据和替代关系；不得静默覆盖历史。

向 `dev-rel` 交接时提供门禁范围、结果、确认级别、有效证据、例外、残余风险和失效条件。`dev-rel`仍需独立检查发布授权和可恢复性。
