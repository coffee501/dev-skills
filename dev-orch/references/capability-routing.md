# 技能选择与主动调用

`dev-orch` 根据用户目标、已有证据和适用条件选取专业 Skill。用户无需指定阶段；明确的“只设计”“只评审”“暂不修改”等范围限制优先。复用有效基线，只运行完成当前目标所需的最短路线。

| Skill | 进入条件 | 主要完成证据 |
| --- | --- | --- |
| `dev-ctx` | 存量行为、影响范围或实现事实不清楚，或既有事实已失效 | 可追溯的现状证据与未知项 |
| `dev-req` | 目标、规则、范围或验收标准存在影响后续工作的缺口 | 可用的 `REQ/RULE/AC` 与待确认项 |
| `dev-hld` | 系统边界、模块职责、数据归属或关键架构决策需要确定 | 可引用的概要设计与验证点 |
| `dev-lld` | 编码所需接口、数据、状态、并发或实现契约不足 | 可执行的详细设计与验证点 |
| `dev-fia` | 存在前端消费方且适用后端契约可引用 | 场景化接口对接说明 |
| `dev-impl` | 用户目标包含实施，输入足以支持编码且变更获授权 | 当前候选、实际差异及构建证据 |
| `dev-cr` | 已有可评审实现候选，或用户明确要求实现评审 | 独立 `REV` 与问题定位 |
| `dev-test` | 需要建立或补足测试场景、用例、数据和预期 | 可追踪的测试设计与可执行路径 |
| `dev-val` | 有可执行验证路径，目标版本、预期、环境和授权满足要求 | 执行证据、缺陷和适用验证结论 |

专业阶段返回后，核对任务身份、输入版本、范围、证据、风险与下游依赖。完成条件满足则结束；存在下游必要阶段则主动推进；出现缺陷、未决问题或输入失效则返回负责阶段并保留历史证据。用户只要求局部阶段时，交付该阶段结果，不自行扩展为完整交付。

Skill 可在当前上下文加载，也可交给独立专业 Agent。对于禁止模型自动调用的专业 Skill，完整读取其核心 `SKILL.md` 后遵循其流程，或交给可执行的专业 Agent；保留普通会话的显式触发策略。根据权限、工作量、并行价值和独立性选择执行上下文；Skill 调用不提升工具权限。`dev-impl` 后的正式 `dev-cr` 优先使用独立评审上下文；无法隔离时只有 `dev-cr` 按项目政策记录充分补偿控制和证据，才能考虑 `Approved`，同一上下文自查不能直接批准。子代理不可用时可等待容量或顺序完成仍有权限的工作，不能把容量限制记录为专业失败。

每次调用传递目标、输入版本、责任范围、允许动作、预期输出、验证方式与停止条件。失败后保存证据，依据新信息纠偏；相同输入、相同方法反复失败时停止重试，报告阻塞与恢复条件。
