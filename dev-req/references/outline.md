# 需求文档目录

## 完整需求文档结构

正式产物先记录 `CHG`、版本、状态、来源和适用范围。以下是可裁剪的输出结构；按变更规模选择适用章节，不为空模板补内容。具体检查维度见[需求分析框架](requirement-framework.md)。

1. **背景、目标与范围**：来源、成功目标、非目标、优先级和适用范围；存量变更说明 As-Is、To-Be 和差异。
2. **角色、场景与业务对象**：参与者、使用条件、对象关系和术语。
3. **业务流程、状态与异常结果**：正常与异常路径、状态变化、通知及业务结果。
4. **功能需求**：按业务能力描述已确认的 `REQ`，明确触发条件和可观察结果。
5. **业务规则与数据要求**：分别描述已确认的 `RULE`、数据口径、数据变化和一致性要求。
6. **权限与数据范围**：谁可以操作、查看哪些数据，以及拒绝后的结果；按适用性展开。
7. **集成、质量与兼容约束**：上下游影响及有依据的性能、安全、审计和兼容要求；检查适用性后展开。
8. **验收标准与追踪**：已确认的 `AC` 及其与来源、`REQ`、`RULE` 的关系。
9. **冲突、待确认项与基线结论**：说明未决问题的影响；存在未解决的 P0 时保持“需求草案”。

用户可观察的展示或交互结果写入对应功能需求，不单设通用 UI 章节。业务生效、历史和在途数据及兼容限制写入相关章节；发布、灰度、切换和回滚的执行方案不属于需求正文。
