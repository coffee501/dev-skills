# Dev 体系交接协议

## 使用原则

跨 Skill 传递正式工作时创建 `HOF`。普通引用不需要交接包；发生责任转移、阶段推进、阻塞返回或失效通知时必须使用。

## 标准交接包

| 字段 | 要求 |
| --- | --- |
| `id` | 稳定 `HOF-001`；无权威登记时使用临时编号 |
| `change` | 关联 `CHG` |
| `from` / `to` | 来源和目标 Skill 或正式责任流程 |
| `reason` | 阶段推进、问题返回、重新评审、执行失败或运行反馈 |
| `inputs` | 产物编号、版本和适用范围 |
| `preserved_behavior` | 下游不得改变的规则、契约和结果 |
| `decisions` | 已接受决策及确认依据 |
| `unresolved` | P0/P1/P2、责任方、影响和解除条件 |
| `invalidated` | 已失效或需要复审的下游产物和证据 |
| `expected_outputs` | 目标流程需要交付的产物类型 |
| `entry_conditions` | 目标流程开始前必须满足的条件 |
| `owner` | 交接和接收责任角色 |

## 交接状态

使用 `Prepared → Acknowledged → Accepted / Rejected → Superseded`。

- 来源 Skill 只能创建 `Prepared`。
- 发现目标流程、输入版本或责任方不正确时标记 `Rejected` 并说明理由。
- 没有接收证据时不得假定已经 `Accepted`。
- 新交接替代旧交接时保留旧编号和后继关系。

## 严重度和优先级

- P0/P1/P2表示来源侧问题严重度。
- 目标流程单独判断处理优先级和影响。
- P0只阻塞受影响分支；其他有可靠输入的工作可以继续。
- 风险接受必须记录权限、依据、范围、到期时间和失效条件。

## 交接路由

| 问题 | 目标流程 |
| --- | --- |
| 当前实现、调用链、业务流程或技术上下文未知 | `dev-ctx` |
| 业务目标、规则、状态、数据语义、验收 | `dev-req` |
| 系统边界、职责、数据权威、总体一致性 | `dev-hld` |
| 字段、接口、事务、错误码、实现机制 | `dev-lld` |
| 代码、配置、迁移或自动化实现 | `dev-impl` |
| 测试覆盖、用例、数据和预期 | `dev-test` |
| 执行、证据、失败分类和质量门禁 | `dev-val` |
| 部署、迁移执行、观察和回滚 | `dev-rel` |
| 运行手册、事故、恢复和持续改进 | `dev-ops` |

合规、SLO、安全授权、外部供应方或项目审批问题路由相应正式责任流程，不强行塞入错误的 `dev-*` 模块。
