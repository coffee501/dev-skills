# 实现评审输出目录参考

向用户呈现评审就绪诊断、完整或局部评审、专项评审、整改复审和评审审计时读取本文件。按请求范围选择适用章节；局部结果可合并，不为目录完整生成空内容。`REV/HOF` 的字段与状态由内部协议管理，本文件只规定可读表达。

## 目录

1. [评审结论与范围](#1-评审结论与范围)
2. [发现与整改建议](#2-发现与整改建议)
3. [覆盖、证据与限制](#3-覆盖证据与限制)
4. [复审变化与后续行动](#4-复审变化与后续行动)

## 1. 评审结论与范围

先说明用户需要的结论：当前候选是通过、需整改，还是因输入不足无法判断；给出依据。标明仓库、候选 base/head 或工作区快照、实际审查范围、排除范围和适用的 `REV` 版本。就绪诊断只报告可审查性；局部代码建议不能写成完整候选获批。

## 2. 发现与整改建议

按 P0、P1、P2 排序。每项说明具体位置、触发条件、可复核证据、实际影响、最小整改目标和验证要求，并区分实现缺陷与需求、设计或测试预期缺口。没有可执行发现时明确说明，不为填充报告制造问题。

## 3. 覆盖、证据与限制

概述已检查的关键实现路径、相关需求和设计、适用检查结果及其证据位置。说明未检查文件或行为、无法运行的检查、外部依赖与独立性限制，以及这些限制对结论的影响。检查通过或没有发现问题都不能替代范围与限制说明。

## 4. 复审变化与后续行动

复审时列出原发现的处置、新差异、新发现、保留风险和后继结论。按需说明整改责任、再次评审的条件、验证重点和下一责任方。正式交接仍使用内部 `HOF`；面向用户只概述交接事项和阻塞条件，可引用协议编号而不展示原始字段。

报告是指定候选、`REV` 及实际证据的只读表达；来源变化后重新评审或更新报告，不在报告中另设批准状态。
