## 观察目标

观察用于判断当前发布批次是否达到后置条件、是否可以扩大范围以及是否需要停止或恢复。不要只检查进程存活、平台Ready或单个技术指标；按发布设计覆盖业务结果、错误、延迟、资源、数据不变量、队列、任务、外部依赖和安全信号。

## 基线和窗口

发布前记录可比较基线、时间范围、流量、数据规模、已知异常和环境事件。观察窗口来自已接受设计或授权计划；没有确认时长时保持阻塞，不自行编造固定等待时间。

区分即时健康、灰度窗口、全量窗口和长期运行。短期OBS健康不代替SLO或长期生产稳定判断。

## 指标与证据

每个观察项记录来源、查询或面板、维度、基线、允许范围、当前值、采样和延迟、责任人、停止条件和数据质量限制。保留部署事件、告警、日志、追踪、业务对账和人工核对的定位器；脱敏秘密和个人信息。

指标缺失、延迟、采样不足或查询错误时标记未知，不按零值或无告警解释为健康。

## 决策表

| 动作 | 使用条件 |
| --- | --- |
| 继续 | 当前批次后置条件满足，强制指标处于允许范围 |
| 保持观察 | 样本或窗口不足，当前状态仍安全稳定 |
| 暂停 | 影响未知，需要冻结当前范围调查 |
| 有限重试 | 步骤幂等，失败原因明确且仍在授权范围 |
| 回滚 | 回滚条件命中且旧版本可处理当前数据、状态、契约和消息 |
| 补偿/前向修复 | 变化不可逆且已有批准方案 |
| 事故交接 | 已产生生产影响，需要止损、恢复、沟通或超出常规发布边界 |

决策必须引用实际OBS和授权条件，不因发布时间压力跳过停止门。

## OBS结论

状态使用 `Planned → Active → Healthy / Degraded / Failed / Closed`。

- `Healthy`：当前范围和规定窗口满足全部强制观察条件。
- `Degraded`：仍在控制范围，但存在偏差、有限能力或已接受风险。
- `Failed`：停止条件命中或发布目标不满足。
- `Closed`：观察因回滚、替代、窗口转交或其他明确原因结束，不暗示健康。

DEP成功但OBS失败时REL不得完成。形成正式验证证据或重算质量门时交接 `dev-val`。
