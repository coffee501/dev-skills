## 三平面模型

- **控制面**：管理发布范围、候选、授权、窗口、批次、依赖、停止和恢复条件。
- **执行面**：使用项目已有工具执行应用、配置、契约、迁移、开关和流量变化。
- **观察决策面**：根据基线、指标、业务结果和数据不变量决定推进、暂停、重试、回滚或停止。

三个平面共享同一 `REL`，但状态和证据分开记录。命令成功不自动意味着观察健康或发布完成。

## 工作对象

| 产物 | 责任 |
| --- | --- |
| `REL` | 发布目标、批准范围、候选、批次、策略和最终状态 |
| `DEP` | 一次部署、配置、契约、开关或流量执行批次 |
| `MIGRUN` | 一次Schema、数据、配置或运行状态迁移执行 |
| `OBS` | 发布前基线、批次观察、停止判断和最终观察结论 |

一个REL可以包含多个DEP、MIGRUN和OBS。目标、候选、环境、批准范围或恢复边界发生实质变化时增加版本或建立后继REL，不静默覆盖。

## 发布批次

每个批次具有一个主要目标，至少记录：来源步骤、目标环境和部署单元、执行入口、候选和配置版本、前置与后置条件、超时和资源上限、停止与恢复动作、观察窗口、原始记录位置和责任角色。

按照设计表达批次依赖。串行仅用于真实依赖；可以并行的单元也必须具有隔离和独立停止边界。

`DEP` 状态使用 `Planned → Ready → Running → Succeeded / Failed / Blocked / Aborted / RolledBack`。

`MIGRUN` 状态使用 `Planned → Ready → Running → Verified / Failed / Blocked / Aborted / Compensated / ForwardFixed`。

`OBS` 状态使用 `Planned → Active → Healthy / Degraded / Failed / Closed`。

## 独立调用

没有正式Dev产物时，可以使用项目发布单、流水线记录、制品摘要、外部质量门和用户明确范围作为输入。使用 `CHG-PENDING-*` 和本地产物编号，不虚构正式确认。

外部质量门需要映射来源、候选、环境、规则、结论、例外和新鲜度。非生产发布可以在明确范围内独立执行；生产发布仍需精确授权、停止和恢复条件。

## 完成语义

分别判断：发布就绪、批次执行成功、迁移验证完成、观察窗口健康、运行交接完成。只有全部适用条件满足时REL才能进入 `Completed`。观察失败、迁移差异未解释或运行交接缺失时不得因部署命令成功而完成发布。
