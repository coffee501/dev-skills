# 生产操作安全

## 目标

在事故压力下仍保持目标、权限、动作、停止和恢复边界清晰。Runbook、紧急程度或口头指令都不能替代本次操作授权。

## 操作前安全门

任何L2至L4操作前确认：

| 维度 | 必须明确 |
| --- | --- |
| 目标 | 环境、账号/租户、区域、集群、服务、实例或数据集 |
| 身份 | 实际执行身份、责任角色、最小权限和审计入口 |
| 授权 | 批准人/系统、时间、范围、动作类别和有效期 |
| 当前状态 | 版本、配置、流量、依赖、数据及已知影响 |
| 动作 | 实际命令或平台操作、参数、批次和最大影响面 |
| 停止 | 指标、错误、时间、数量或未知状态的停止条件 |
| 恢复 | 回退、解除隔离、恢复流量、检查点或前向修复路径 |
| 验证 | 业务、技术、数据、依赖和用户影响的成功条件 |
| 证据 | 日志、审计、输出、前后状态和时间线保存位置 |

任一项无法确定时，停止状态变更，只做安全的只读发现、证据保全和升级。

## 安全级别

- L0/L1不触达生产状态，可以准备、评审和演练。
- L2只读查询也要限制范围，避免全表扫描、过量日志导出或敏感数据泄露。
- L3必须来自当前有效Runbook或项目批准的等价程序；先单目标或最小批次，验证后再扩大。
- L4要求专门授权、Dry Run、备份或检查点、双人或平台强制复核以及失败恢复。无法证明可控时不得执行。

## 禁止默认执行

- 目标包含通配符、未解析变量、默认订阅/账号或模糊的“线上”。
- 复制历史命令但无法证明当前版本、拓扑和权限仍适用。
- 删除、覆盖、回填、重放、补发或批量更新数据而无精确选择条件和校验。
- 清空队列、缓存或任务状态而未分析丢失、重复和顺序影响。
- 用无限重试、全量重启或全量扩容掩盖未知故障。
- 在聊天、日志或产物中暴露密钥、令牌、个人数据或受限业务数据。
- 在事故中临时生成脚本并直接对生产运行；需要实现时交给 `dev-impl`，需要发布时交给 `dev-rel`。

## 执行控制

1. 保存操作前快照和关键指标。
2. 展开并人工/平台核对最终目标，不依赖隐式当前上下文。
3. 使用最小批次、速率和并发度。
4. 每步单独记录，不把多个有副作用动作隐藏在一个不可观察命令中。
5. 校验退出码、平台状态和业务后置条件；命令成功不是业务成功。
6. 达到停止条件、超出授权、证据矛盾或出现未知副作用时立即停止扩大范围。
7. 记录实际差异，不把预期步骤写成已执行事实。

## 凭据与敏感信息

使用临时、最小权限和可审计凭据。引用凭据标识而不是复制秘密；证据输出先分类和脱敏。凭据轮换本身属于L4，必须同时处理生产者、消费者、缓存、在途会话和回退窗口。

## 数据恢复附加条件

明确数据权威方、选择集合、预期条数、幂等性、事务边界、并发写入、约束、审计和对账。先生成差异，后执行写入；执行后用独立查询或业务对账验证。备份存在不代表可恢复，必须知道恢复时间、恢复粒度和验证方式。

## 失败处理

动作失败后保留首次失败和全部尝试。只有失败原因明确、动作可幂等且仍在授权范围内时才有限重试。无法安全回退时保持隔离，声明当前风险并升级，不自行扩大为新的恢复方案。
