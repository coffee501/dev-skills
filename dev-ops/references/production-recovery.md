# 生产恢复与稳定验证

## 恢复目标

恢复是把声明的用户和业务影响降到可接受范围，并证明系统、数据和依赖处于可持续状态。它不等于命令成功、实例存活、单一指标变绿或事故关闭。

## 恢复策略优先级

1. 停止继续损坏或错误副作用。
2. 使用已批准、最小范围、可逆的止损路径。
3. 恢复核心业务结果和数据不变量。
4. 恢复非核心能力、积压任务和完整容量。
5. 清理临时措施并交接永久修复。

策略包括隔离、降级、故障切换、受控重启、限流、扩缩容、开关、回滚、补偿、重放、数据修复和前向修复。具体策略必须已有设计或授权；本 Skill 不在事故中发明不可验证的永久方案。

## 恢复判据

至少从以下维度选择与事故影响对应的信号：

| 维度 | 示例 |
| --- | --- |
| 业务 | 成功率、订单/支付/同步结果、处理时效、关键用户路径 |
| 用户 | 报错、延迟、可访问性、支持工单、特定租户结果 |
| 技术 | 错误率、延迟、吞吐、饱和度、进程与依赖健康 |
| 数据 | 完整性、唯一性、余额/计数、状态一致、对账差异 |
| 异步 | 队列积压、最老消息年龄、重试、死信、重复和顺序 |
| 依赖 | 上下游可用性、契约、限额、证书、网络和供应方状态 |
| 安全 | 未授权访问、泄露、重放、审计和密钥状态 |

每项定义基线、阈值、观察窗口、数据来源、采样范围和已知盲区。

## 冲突处理

技术指标健康但关键业务仍失败时，不得声明恢复。用户报告与自动监控冲突时，定位受影响租户、版本、区域、缓存或数据分片，保留两类证据。数据不变量未知时，服务恢复只能标记为局部或暂定，并升级数据核验。

## 数据与状态恢复

执行前建立待处理集合和不可变差异；确认权威数据源、在途写入、事务/锁、幂等键、重复副作用、顺序和审计。先小批次或单对象，验证后扩大。完成后独立对账，并记录未处理、跳过、失败和人工例外。

重放消息或任务前确认消费者幂等、顺序、过期规则、外部副作用和当前版本兼容。不能用“至少一次”语义作为重复安全的证明。

## 稳定观察

观察窗口从最后一个可能影响判定的动作后开始。窗口覆盖业务周期、异步积压消化、缓存/会话过期和依赖恢复时延。记录临时容量、绕行、关闭功能、降级、手工任务和额外值守。

观察期间达到停止/复发条件时回到事故响应。健康窗口只支持当前范围和时间，不保证长期稳定。

## 临时措施退出

每项临时措施必须有所有者、最大保留时间、退出条件、撤销步骤、验证和失败处理。需要代码、设计、测试或发布的退出工作形成CAPA和交接。无法撤销的措施是新的风险，不应隐藏在“已恢复”中。

## 恢复记录

记录恢复目标、批准依据、实际动作、前后差异、业务/技术/数据证据、观察窗口、残余影响、盲区、临时措施、责任人和结论失效条件。只有有权限责任方能够确认风险接受或事故关闭。
