# 证据与时间线

## 目标

让事故决定、恢复结论和RCA能够回到可验证的生产事实，避免事后记忆、时区错位、日志覆盖或推测污染证据。

## 证据来源

- 指标、告警和仪表盘查询。
- 应用、网关、数据库、中间件和平台日志。
- 分布式追踪、请求ID、消息ID和业务对象ID。
- 审计、发布、配置、开关、凭据和流量变更记录。
- 数据差异、对账、备份、检查点和恢复输出。
- 用户、客服、业务、供应方和状态页报告。
- 命令、平台动作、聊天决定和沟通发布记录。

转述和报告可以是证据来源，但必须标记来源、采集时间和可信度，不能与原始机器证据混为一类。

## 时间规范

统一使用带时区的ISO-8601时间。保留来源原始时间、解析后的统一时间、来源时区、已知时钟偏差和采集时间。只有日期或相对表达时标为不精确，不虚构秒级顺序。

## 时间线条目

每条至少包括：

- `occurred_at`：事件发生时间。
- `recorded_at`：进入记录的时间。
- `kind`：`fact / hypothesis / decision / action / observation / communication / correction`。
- `actor/source`：责任角色或系统。
- `content`：简明陈述。
- `evidence_refs`：原始定位器、查询或快照。
- `confidence`：适用于假设或间接事实。
- `supersedes/corrects`：更正或替代关系。

不要覆盖错误条目；新增 `correction` 并说明依据。

## 完整性与保全

尽早保存易过期数据，记录查询条件、时间范围、版本、采样、过滤和时区。原始数据保持只读，分析副本说明转换。可用时保存摘要、哈希、审计ID或不可变位置；不要为了集中归档而复制超出权限的敏感数据。

## 事实与推断

- 事实：可由定位器或多个可信来源复核。
- 观察：当时看到的结果，可能受采样和盲区限制。
- 假设：解释事实的待验证模型。
- 决定：基于当时证据做出的选择及其授权。
- 根因结论：被证据和排除路径支持的因果机制。

使用“相关”“先于”“触发”“导致”时明确证据强度。时间接近只支持相关性，不自动支持因果关系。

## 冲突与缺口

记录冲突来源、各自适用范围、时间、采样和可能解释。无法消解时保留为开放问题，并限制恢复或RCA结论。缺失日志、监控盲区、时钟偏差和采样不足本身是检测/响应缺口，可形成CAPA。

## 脱敏与访问

按数据分类最小化收集，移除密钥、令牌、个人信息和无关业务数据。保留受限原始证据的位置和访问责任，不把敏感内容复制到普通文档。对外材料使用经过批准的派生摘要。
