# 来源权威与冲突处理

## 来源分工

| 来源 | 可以证明 | 不能单独证明 |
| --- | --- | --- |
| `REQ/RULE/AC` | 目标业务行为、规则、状态和验收 | 当前代码已经实现 |
| `DEC/MOD/FLOW` | 系统边界、职责、权威方和协作模式 | 字段级接口已经落地 |
| `API/EVT` 详细设计 | 目标接口、事件、字段、错误和治理语义 | 生产实现与文档一致 |
| OpenAPI 等机器契约 | 可解析的结构、类型、必填、安全和样例 | 业务调用顺序、字段用途和异步最终性 |
| 代码、测试、配置 | 当前版本可观察的实现事实 | 当前行为是正确需求或必须长期兼容 |
| 运行证据 | 特定版本、环境和条件下的实际结果 | 其他版本和环境同样成立 |
| 既有 FIA | 历史对接约定和消费方认知 | 仍然当前有效 |

## 证据标签

每条关键结论按需标记为：`Confirmed`、`ImplementationFact`、`Inference`、`Conflict` 或 `Unknown`。推断必须给出依据和确认责任方；未知不使用默认值填补。

## 冲突规则

1. 先区分“目标语义”和“当前实现”，不要用一个来源覆盖另一个来源。
2. 同一层级优先采用已确认、版本匹配、范围匹配且更新更晚的权威来源。
3. OpenAPI 与实现不一致时记录契约漂移，不能默认任一方正确。
4. 业务语义冲突返回 `dev-req`；架构权威冲突返回 `dev-hld`；字段和接口冲突返回 `dev-lld`；实现偏离返回 `dev-impl`。
5. 冲突影响当前场景正确接入时为 P0；可以隔离且有明确临时约束时可评为 P1。

## 安全取证

只读取用户授权范围内的仓库、文档和环境。示例必须脱敏；不得复制令牌、Cookie、个人信息、真实支付数据或生产响应。没有授权时不调用真实外部接口或生产系统。
