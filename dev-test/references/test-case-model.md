## 场景与用例边界

`TSC` 描述要覆盖的风险或行为；`TC` 描述一次可执行验证。一个场景可以由多个用例覆盖，一个用例应有一个主要验证目标。不要让用例编号替代上游需求和设计编号。

## 测试场景

每个 `TSC` 记录：名称、关联 `SRC/REQ/RULE/AC/VAL/DVAL/RISK/CONTRACT/DEFECT` 及来源版本、风险、前置状态、触发、参与模块或系统、输入类别、正常与失败结果、判定依据、状态和数据副作用、推荐测试层级、优先级和需展开用例。

优先建立核心成功、规则拒绝、状态不变量、边界、权限、重复并发、外部失败、兼容迁移和重大非功能风险场景。

## 测试用例

每个 `TC` 至少包含：

| 内容 | 要求 |
| --- | --- |
| 编号和名称 | 稳定、体现行为与结果 |
| 追踪 | 关联 TSC、有效来源、VAL/DVAL和实现对象 |
| 优先级 | 说明风险依据 |
| 前置条件 | 身份、状态、数据、配置、版本、依赖 |
| 测试数据 | 引用 TDP/TD，不把敏感生产数据写入文档 |
| 执行步骤 | 可操作、顺序明确、无隐含判断 |
| 预期结果 | 每个关键动作都有可观察断言 |
| 判定依据 | 需求、契约、不变量、独立参考或批准结果 |
| 清理 | 数据、消息、任务、配置恢复 |
| 生命周期 | Draft、Ready、NeedsReview、Deprecated 或 Superseded |
| 执行方式 | Manual、AutomationCandidate 或已映射 AUT 的 Automated |

## 步骤与预期

步骤描述测试行为，不描述实现代码。预期结果按适用范围检查：返回值、状态、持久化数据、外部调用、副作用、事件消息、日志审计、指标告警以及不应变化的对象。注明 oracle 来源，不能用被测实现的同一算法、查询或转换生成预期结果。

异步结果说明等待条件、最大业务时限、轮询或事件观察方式；没有确认时限时列为缺口。禁止使用固定睡眠代替确定完成条件的设计。

错误预期需要明确错误类别、稳定错误码或业务结果；内部堆栈和敏感信息不得作为对外预期。

## 数据与环境

`TDP` 表示抽象等价类、边界类或数据分区；`TD` 表示可执行数据集或夹具；`TENV` 表示环境拓扑、服务和契约版本；`TCOND` 表示依赖状态、时间与时区、消息积压、网络或故障条件。分别记录生成、约束、敏感性、复用、清理和适用版本。

优先使用最小数据集证明目标。时间相关测试使用可控时钟或明确时间源；外部依赖替身必须保持被验证契约，不能把 Mock 行为当作真实能力证明。

## 用例质量

进入 `Ready` 前确认：

- 一个主要目标，名称与断言一致
- 前置条件和数据可以准备
- 步骤不依赖测试人员猜测
- 预期结果具体且可观察
- 正负路径与边界选择有风险依据
- 清理和隔离可执行
- 追踪到上游和实现对象
- 不在同一层级重复提供相同证据；跨层互补验证说明各自证明的边界
- 自动化建议与测试层级匹配

测试优先级使用 `Critical/High/Medium/Low`；P0/P1/P2 保留给设计问题严重度。上游语义、契约、实现、数据、环境或自动化断言变化时，受影响 `Ready` 用例进入 `NeedsReview`。某次执行的 `NotRun/Passed/Failed/Blocked/Skipped` 结果记录批次、时间、代码和契约版本、环境、证据和失效条件，不改变 `TC` 生命周期。
