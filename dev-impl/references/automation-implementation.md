# 测试自动化实现

## 所有权

`dev-test` 拥有 `TC/AUT` 的目标、预期、数据分区和自动化规格；`dev-impl` 实现测试代码、夹具和执行入口；
`dev-val` 运行它们并产生 `RUN/EVD/GATE`。

建立：

> `TC → AUT → IMP(kind=test-automation) → BUILD → RUN/EVD`

不得由测试代码反向改变 `TC` 预期，也不得把代码存在写成 `AUT` 规格已确认或门禁已启用。自动化代码状态使用
`IMP(kind=test-automation)`；`AUT` 规格状态由 `dev-test` 管理；只有进入实际执行门禁并由 `dev-val` 或项目质量
责任方确认后，门禁状态才能标记为 `Enabled`。

## 实现原则

- 选择最低可靠层级，避免用端到端测试替代可在单元、组件或契约层证明的行为。
- 断言业务结果和不变量，不复制被测实现的同一算法生成预期。
- 复用仓库现有框架、夹具、命名和目录结构。
- 数据可隔离、可重复、可清理；时间、随机性和外部依赖可控制。
- 异步测试使用完成条件，不使用固定长睡眠。
- Mock只证明本地契约，不冒充真实外部能力。
- 自动重试不得掩盖首次失败。

## 交付内容

记录关联 `AUT/TC`、代码位置、框架、数据准备、依赖策略、断言、执行入口、适用版本、并行能力和稳定性风险。无法自动化时说明原因并保留人工执行方式。

## BUILD 边界

本地运行自动化可以形成 `BUILD`，用于证明测试代码可加载和在指定条件下工作。稳定性、目标环境适用性和正式验证结论交给 `dev-val`。
