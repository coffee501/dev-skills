# 实施安全门

## 操作分级

| 等级 | 典型操作 | 默认处理 |
| --- | --- | --- |
| L0 | 只读搜索、状态检查、实现计划 | 可在任务范围内执行 |
| L1 | 工作区内代码、测试和文档修改 | 用户明确要求实现后执行 |
| L2 | 安装依赖、生成迁移、修改共享配置或生成代码 | 先确认必要性、影响和恢复方式 |
| L3 | 执行数据迁移、调用真实外部服务、修改共享环境 | 按环境和责任路由，不能只凭用户要求直接执行 |
| L4 | 生产、不可逆数据、基础设施或流量操作 | 不属于 `dev-impl`，交接 `dev-rel/dev-ops` |

## 修改前检查

确认目标仓库、允许范围、仓库规则、工作区状态、用户现有修改、目标版本、数据分类、外部副作用、凭据、资源和恢复方式。目标或环境身份未知时不得假设安全。

对用户已有修改：

- 将其视为受保护输入，不回退、不覆盖、不清理。
- 与目标修改重叠时先理解并适配；无法安全合并时形成阻塞。
- 禁止使用破坏性Git操作恢复工作区。

## 代码与依赖

- 使用 `apply_patch`进行手工文件编辑。
- 优先使用已有依赖、工具和模式；新增依赖必须有明确必要性。
- 安装或升级依赖前检查锁文件、许可证、运行环境、兼容性和可回退方式。
- 不执行来源不明脚本，不输出凭据或敏感配置。
- 生成代码前确认权威Schema和生成命令，避免手工与生成物双重维护。

## 数据、配置和外部副作用

- 迁移文件可以在工作区生成和静态验证；实际迁移执行按环境和风险交接。
- 不使用生产数据、真实生产凭据或真实计费资源进行本地实现检查。
- 真实邮件、短信、支付、签名、工单和供应商调用默认禁用或使用沙箱。
- 删除、覆盖、重命名或不可逆转换现有数据前明确精确目标与恢复能力。

## 环境与执行路由

- 本地或任务专属临时隔离环境由 `dev-impl` 在授权范围内使用。
- 正式测试环境中的测试执行和证据治理交接 `dev-val`。
- 预发或生产部署、计划性迁移、配置和流量切换交接 `dev-rel`。
- 事故期生产恢复和数据修复交接 `dev-ops`。
- 调用真实外部服务前确认环境所有者、凭据范围、费用、副作用、速率、清理和停止条件；任一不明确时停止并交接。
- 用户要求直接操作生产不构成 `dev-impl` 的例外授权。

## 命令执行

- 先执行最小、快速、低副作用的检查，再逐步扩大。
- 为构建、测试和生成命令设置合理超时，避免无界负载。
- 命令可能修改共享系统、安装软件、产生费用或访问外部生产服务时停止并交接。
- 失败后读取实际输出并定位类别，不通过无限重试掩盖问题。

## 完成清理

检查临时进程、生成文件、测试数据、缓存、配置和工作区状态。只清理由本次任务创建且已确认可删除的临时资源。记录无法清理的残留、影响和责任方。
