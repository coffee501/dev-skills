# 实现进度与交付输出目录参考

向用户汇报实现诊断、部分进度、完整交付、缺陷修复、重构或整改时读取本文件。按当前范围选择适用章节；局部工作可合并，不为目录完整生成空内容。`IMP/BUILD/HOF` 的字段与状态由内部协议管理，本文件只规定可读表达。

## 目录

1. [当前进度与范围](#1-当前进度与范围)
2. [需求、设计与实际修改](#2-需求设计与实际修改)
3. [行为与工程影响](#3-行为与工程影响)
4. [本地检查与证据](#4-本地检查与证据)
5. [偏差、风险与下一步](#5-偏差风险与下一步)

## 1. 当前进度与范围

先说明候选身份、变更目标、已完成、未完成或受阻内容，以及明确排除范围。诊断或部分实施时说明可以继续的工作和恢复条件；完整交付时说明本次交付边界。注明所依据的 `IMP/BUILD` 版本或工作区快照，但不把内部状态字段当作报告正文。

## 2. 需求、设计与实际修改

将适用需求与设计、实际修改的文件或符号、已实现行为对应起来。仅对需要追踪的实现单元使用简表；局部修复直接说明根因条件、修改位置和对应的预期结果。未实施范围与设计偏差如实列出，不用计划内容冒充已修改代码。

## 3. 行为与工程影响

说明可观察行为变化及已核实的保持项。按适用性说明 API、事件、Schema、数据、配置、迁移、任务、依赖和测试自动化的影响，以及兼容与恢复边界；未受影响的类别无需逐一填空。

## 4. 本地检查与证据

列出实际运行的检查、结果、关键证据位置和适用限制；未运行的检查说明原因与影响。失败与重试保留首次失败，不把本地 `BUILD` 通过写成独立评审或正式验证通过。需要复核命令、环境或时间时引用内部记录。

## 5. 偏差、风险与下一步

说明未决设计偏差、阻塞、剩余风险、需要复审或重新验证的范围，以及下一责任方和恢复条件。面向用户概述评审或验证所需关注的事项；正式跨流程交接仍使用内部 `HOF`，不展示其原始字段。

完整实现或跨多个实现单元时使用上述适用章节形成交付摘要；局部或进行中的工作使用精简进度。两者都是当前 `IMP/BUILD` 与实际差异的无独立状态只读视图，来源变化后重新生成，不新增批准、完成或验证结论。
