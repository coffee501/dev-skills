# 迁移实现

## 适用范围

用于数据库Schema与数据、接口或事件契约、配置格式、缓存内容、文件格式和运行状态迁移。实际生产执行归 `dev-rel`，事故期数据修复归 `dev-ops`。

## 实现要求

- 引用 `MIG/DATA/API/EVT/CFG`及版本，明确权威来源。
- 说明迁移前、过渡期和迁移后允许的读写行为。
- 覆盖混合版本、旧写新读、新写旧读及在途对象。
- 设计可重复执行、断点续跑、部分失败、对账和清理。
- 对大数据量使用分批、限速、进度和停止条件，不在实现阶段执行生产负载。
- 记录不可逆变化、回滚限制和前向修复入口。

大数据量或在线迁移还必须从已批准设计获得：当前数据量和增长速度、峰值读写、锁等待预算、复制延迟阈值、批次
大小、执行窗口、资源预算、备份/PITR或前向恢复能力、新旧字段权威切换点以及旧结构清理门槛。缺少这些输入时
可以实现通用迁移机制和隔离验证，但不得建议生产迁移就绪。

## 数据库迁移

分别检查Schema兼容、数据回填、索引或约束建立顺序、锁与资源风险、应用发布顺序和旧版本可读性。迁移成功不能只依据脚本退出码；准备数量、校验和、语义抽样或不变量校验。

## 契约迁移

优先使用新增兼容字段、双读双写、版本化消费者或适配层等已批准策略。禁止在没有调用方处理方案时直接删除或改变字段语义。生成物和文档引用同一权威契约。

## 本地检查

允许生成迁移文件、检查语法、运行隔离数据集、验证重复执行和恢复逻辑。大表迁移的 `BUILD Passed` 不证明真实
锁时间、复制延迟、资源占用或生产窗口可接受，必须在面向 `dev-val/dev-rel` 的 `HOF` 中列为容量和运行验证项。
共享或生产环境迁移形成面向 `dev-rel` 的 `HOF`，包含版本、顺序、窗口、限速、观察、验证、停止和恢复条件。
