## 使用原则

按设计深度和问题特点选择章节，不强制填满。局部变更可以合并章节；关键生产设计展开全部有依据内容。概要设计结论只引用编号和必要上下文，不复制全文。

## 1. 设计依据、范围与约束

### 1.1 编写目的

说明详细设计要指导的编码、数据变更、接口实现、配置、发布、回滚和验证活动。

### 1.2 输入依据

列出：

- `REQ`、`RULE`、`AC`
- `DEC`、`MOD`、`FLOW`、`VAL`
- 代码、数据库、接口、配置、部署和运行资料
- 外部系统契约
- 安全、性能、合规及工程约束

### 1.3 设计范围与非范围

明确本次涉及的模块、功能、数据、接口、任务、配置、代码库和部署单元，以及不处理内容。

### 1.4 设计假设与待确认事项

区分已确认、实现证据、合理推断、待确认和冲突。说明未决问题影响哪些实现单元。

### 1.5 输入追踪

建立 `REQ/RULE → AC → DEC/MOD/FLOW → DET/DDEC` 映射。

### 1.6 文档与决策治理

记录文档状态、版本、适用范围、确认依据和替代关系。项目存在正式评审流程时，记录确认人或责任角色、确认时间及证据；对未决事项记录责任方、目标时间、状态和关闭证据。

## 2. 实现架构与程序结构

### 2.1 概要设计继承

引用系统边界、模块职责、数据归属、交互原则、部署约束和关键 `DEC`。不要重新选择架构。

### 2.2 技术与工程约束

说明语言、框架、工程规范、分层、持久化、通信、中间件、复用组件和运行环境。

### 2.3 程序结构

说明实际采用的 Controller、Application Service、Domain Service、Repository、Adapter、Handler、Job 等结构及依赖方向，不强制套用固定分层。

### 2.4 已有实现基线

对存量系统说明入口、核心符号、调用链、数据访问、外部契约、配置、部署、测试和已知运行行为，并附证据。

### 2.5 目标实现与差异

说明目标结构、变化点、保持项、受影响对象、临时实现和退出条件。

## 3. 模块与功能详细设计

这是详细设计主体。按 `DET` 组织，不必按代码文件机械拆分。每个设计单元使用 [implementation-unit.md](implementation-unit.md) 中的适用项目。

### 3.1 设计单元清单

记录编号、名称、职责、关联需求、概要模块、依赖和实现位置。

### 3.2 设计单元详细说明

至少覆盖：

- 目标、职责与非职责
- 输入、输出和前置条件
- 正常、分支和失败流程
- 业务规则和状态变化
- 数据读写与接口交互
- 事务、并发和幂等
- 权限、异常、日志、监控和配置
- 兼容与迁移要求
- 验证点

### 3.3 程序对象和扩展点

只对核心类、组件、方法、策略和扩展点说明职责、参数、返回值、生命周期和线程安全要求。不展开普通访问器或无业务含义的映射代码。

## 4. 核心流程、时序与状态

### 4.1 程序处理流程

说明模块内部调用、校验、分支、状态落库、外部调用、事件发布和返回结果。复杂分支、关键算法、事务与副作用顺序、并发幂等、补偿恢复或批处理续跑仅靠正文无法无歧义实现时，按 [implementation-unit.md](implementation-unit.md) 补充伪代码；简单 CRUD 和框架样板不生成伪代码。

### 4.2 跨模块时序

展示同步与异步调用、事务位置、状态变化、超时、失败传播、重试和补偿。

### 4.3 状态机或状态转换表

说明源状态、触发条件、权限、守卫条件、目标状态、数据副作用、失败结果和是否可逆。

### 4.4 异常与恢复流程

覆盖前置失败、部分成功、重复操作、超时、依赖失败、中断、重放、补偿和人工修复。

## 5. 领域模型与数据存储设计

### 5.1 领域对象与物理模型

说明领域对象到实体、表、文档或缓存结构的映射，以及聚合、引用和数据权威。

### 5.2 物理 ER 图

只展示本次相关实体、主外键和关键基数。

### 5.3 表或集合结构

每个 `DATA` 说明：

- 名称、用途、所属模块和数据权威
- 字段、类型、长度或精度
- 必填、默认值和业务含义
- 主键、外键、唯一、检查和非空约束
- 审计、版本、软删除和敏感字段

### 5.4 索引与访问模式

为索引关联查询、过滤、排序、唯一性和数据规模，说明写入代价和失效风险。不要只列索引名。

### 5.5 数据完整性与生命周期

说明应用校验、数据库约束、引用规则、创建、更新、归档、清理、保留、审计和修复。

### 5.6 数据变更与迁移

为关键迁移分配 `MIG`，说明 DDL 或数据变更顺序、在线兼容、回填、双写或兼容读取、校验、切换、回滚和旧结构删除条件。已有 DDL、ORM 模型或迁移文件时引用其权威定义，不在正文复制另一份完整结构。

## 6. 接口、事件与任务详细设计

### 6.1 同步接口

每个 `API` 说明名称、调用方、协议、路径或服务方法、请求响应字段、校验、错误码、认证、权限、超时、重试、幂等、限流、版本和示例。

项目存在 OpenAPI、Proto 或 JSON Schema 时引用其权威契约，正文只补充无法由机器契约表达的业务与运行语义。

### 6.2 事件与消息

每个 `EVT` 说明业务含义、生产与消费方、触发条件、消息结构、消息标识、分区键、顺序、投递语义、重复、丢失、死信、重放和版本演进。

项目存在 AsyncAPI、Proto、Avro 或其他 Schema Registry 契约时引用权威版本，避免重复维护字段表。

### 6.3 定时与批处理任务

每个 `JOB` 说明触发方式、调度周期、输入范围、游标或分页、并发、重复执行、部分失败、续跑、补偿、超时和监控。

### 6.4 外部依赖和回调

说明契约、责任边界、超时、失败语义、降级、回调认证、乱序和重放处理。

### 6.5 契约兼容

说明新旧字段、新旧消费者、必填性、默认语义、升级顺序、废弃周期和回滚影响。

## 7. 事务、并发与一致性

### 7.1 事务边界

说明事务起止、参与表和操作、提交前后动作，以及禁止纳入事务的远程调用。

### 7.2 并发控制

说明竞争资源、并发不变量、锁或版本位置、锁顺序、冲突检测、冲突结果和重试条件。

### 7.3 幂等实现

说明幂等对象、作用域、幂等键来源、存储位置、有效期、重复结果和失败后的再次调用。

### 7.4 跨边界一致性

说明强一致或最终一致的具体落地、消息与本地事务协作、不一致窗口、状态推进和可见性。

### 7.5 补偿、对账与修复

说明触发条件、补偿动作、重复补偿、对账范围、差异处理、人工入口和审计。

## 8. 安全、可靠性与可观测性

### 8.1 权限与安全

说明认证信息来源、鉴权位置、角色和操作权限、数据过滤、租户隔离、敏感字段、加密或脱敏、防重放、防注入及安全审计。

### 8.2 异常与错误码

定义异常分类、错误码、外部响应、内部上下文、回滚、重试、补偿、告警和人工介入。不得泄露内部或敏感信息。

### 8.3 性能与容量

根据已确认指标设计耗时预算、查询次数、索引、缓存、分页、批量、连接池、线程池、限流和容量。无指标时记录缺口。

### 8.4 可用性与故障治理

说明超时、重试、熔断、隔离、降级、恢复、单点、故障切换和数据修复。

### 8.5 日志、监控与追踪

说明日志事件、级别、字段、Trace ID、业务对象 ID、敏感信息处理、指标、告警条件、责任人和处置入口。

## 9. 配置、兼容、迁移与发布

### 9.1 配置设计

每个 `CFG` 说明名称、用途、类型、默认值、合法范围、环境、作用域、敏感性、动态变更、重启要求、所有者和错误行为。

### 9.2 存量兼容

按 [change-compatibility.md](change-compatibility.md) 说明调用方、历史数据、在途业务、混合版本、报表、任务和运行环境兼容。

### 9.3 迁移与发布顺序

说明应用、数据库、消息、配置和任务的依赖顺序、灰度、开关、观察期、验证门和停止条件。

### 9.4 回滚与前向修复

说明回滚触发、可回滚范围、回滚后的数据和消息处理、不可逆变化、前向修复和恢复目标。

### 9.5 临时设计退出

说明兼容层、双写、旧接口、旧字段、旧任务和旧系统的退出条件、证据、责任人和删除顺序。

## 10. 追踪、AC 映射与验收

### 10.1 实现追踪矩阵

建立 `REQ/RULE → AC → DEC/MOD/FLOW → DET/DDEC → DATA/MIG/API/EVT/JOB/CFG/代码位置 → VAL/DVAL`。

### 10.2 设计验证

覆盖适用的正常、异常、边界、状态、权限、并发、幂等、兼容、迁移、回滚、性能和安全。只定义验证目标、输入边界和通过条件；继承验证使用 `VAL`，详细设计新增项使用 `DVAL`。验证项状态使用 `Planned`、`Passed`、`Failed` 或 `Blocked`，不要使用决策状态。

### 10.3 设计风险与未决问题

列出风险、影响、缓解、验证、责任方、目标时间、状态、关闭证据和阻塞级别。业务问题交接需求流程，架构问题交接概要设计流程；使用主 Skill 规定的结构化交接项。

### 10.4 实现任务拆分

按依赖顺序列出代码、数据库、接口、事件、配置、迁移、监控、验证和清理任务，以及输入、完成条件和回滚要求。

### 10.5 基线结论

明确详细设计草案或基线，并列出未满足条件。

## 图与表达方式

| 问题 | 推荐表达 |
| --- | --- |
| 模块内部多分支、关键算法或执行顺序 | 程序流程图或伪代码；无法由其他表达无歧义覆盖时为必需 |
| 跨模块、跨进程或跨系统调用 | 时序图 |
| 对象复杂生命周期 | 状态机或状态转换表 |
| 复杂对象和程序关系 | 类图 |
| 物理实体关系变化 | 物理 ER 图 |
| 复杂计算、优先级和条件组合 | 公式、决策表或样例 |

一张图或一段伪代码解决一个主要问题。名称、步骤、状态、事务、数据副作用、接口调用和异常必须与正文及权威契约一致。不要为同一逻辑同时维护多份等价表达。
